# CAREFUL: the commit is PINNED on purpose.
# A `git+.../diffusers` with no commit takes the HEAD of the day, which is not a
# bound but a time bomb: diffusers main moved to huggingface-hub>=1.23 while
# transformers<5 requires huggingface-hub<1.0 -> ResolutionImpossible at install
# time, for everyone, overnight. This commit is the one THIS repo was validated
# on (it differs from one fork to the next, see requirements-lock.txt).
# To try a more recent version: replace the hash below, run install.bat again,
# and check that `transformers` still installs.
git+https://github.com/huggingface/diffusers@ed58810cb940e4e38e3d730b4b9c75d4db39cd4f

# transformers 5.x, and not out of taste: the diffusers commit above is the one that
# carries Krea2Pipeline, and it requires huggingface-hub>=1.23 - which transformers<5
# forbids (it requires <1.0). The `<5` bound the other forks carry therefore made this
# file, and requirements-lock.txt with it, impossible to resolve: `pip install` ended
# in ResolutionImpossible on a clean machine and on the CI runner, for everyone.
# Measured on the dev venv that actually runs Krea 2: transformers 5.14, hf-hub 1.24.
# Keep >=5: an older transformers pulls hf-hub <1.0 and the conflict comes straight back.
transformers>=5.0,<6
accelerate
sentencepiece
spandrel

# Required by diffusers to load LoRA weights (load_lora_weights / set_adapters).
# Without it: "PEFT backend is required for this method" -> LoRA silently skipped.
peft

# GGUF quantized single-file transformers (GGUFQuantizationConfig). Lets a quantized
# Qwen-Image .gguf (e.g. Q4_K_M ~11GB) fit in consumer VRAM, fast, no offload. Unlike
# ComfyUI FP8 .safetensors (transformer-only, not loadable by diffusers).
gguf

# declared Content-Length") that spams the console when a response is interrupted.
gradio>=4.44,<6

pillow
numpy

fastapi
